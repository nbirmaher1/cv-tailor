1. SYSTEM OVERVIEW & CURRENT ARCHITECTURAL BASELINE
--------------------------------------------------------------------------------
cv-tailor is a local-first, privacy-respecting career management and CV tailoring
application. It operates with zero marginal API cost by executing headlessly
against the user's local, logged-in Claude Code CLI session (`claude -p`).

Core Tech Stack:
- Backend: Python 3.9+ / FastAPI / Uvicorn (binds strictly to 127.0.0.1:8420)
- Database: SQLite (data/cvtailor.db) with WAL mode, foreign keys, and local auth
- Document Rendering:
  * PDF: Playwright / Chromium headless rendering from HTML templates (templates/default.html)
  * DOCX: python-docx programmatic XML generation (scripts/render_docx.py)
  * DOCX Extraction: python-docx text parser (scripts/extract_docx.py)
  * Length QA: pypdf page count checks (scripts/render_pdf.py) and word/bullet heuristics (scripts/docx_stats.py)
- Frontend: Single-page application using Semantic HTML5, Vanilla JavaScript, and Tailwind CSS.
- Subprocess Engine: claude_runner.py manages `claude -p` streaming JSON output,
  progress step tracking from tool events (Read, WebFetch, WebSearch, Agent, Write, Bash),
  and process cancellation/timeout management.
- Anti-Hallucination Gate: 2-pass review subagent (Agent tool) enforcing cv-standards.md
  to ensure all tailored bullet points and metrics trace strictly to source data.

Data Storage Hierarchy:
- data/
  ├── cvtailor.db (SQLite database)
  └── users/
      └── <user_id>/
          ├── master_cv/
          │   ├── content.json (Canonical structured master CV record)
          │   └── photo.<ext> (Optional candidate headshot)
          ├── applications/
          │   └── <company_slug>/
          │       └── <role_slug>/
          │           └── <attempt_slug_timestamp>/
          │               ├── content.json (Tailored CV JSON record)
          │               ├── output.pdf / output.docx
          │               ├── output.html (For PDF re-renders)
          │               ├── summary.json (AI tailoring rationale and review notes)
          │               ├── metadata.json (Company and role auto-detection)
          │               ├── cover_letter_content.json (Optional)
          │               └── cover_letter.pdf / cover_letter.docx (Optional)
          └── pending/ (Inbox for completed runs where company/role was ambiguous)

2. STRATEGIC PILLARS & DESIGN PHILOSOPHY
--------------------------------------------------------------------------------
1. Local-First & Zero Cost:
   All personal candidate data, resumes, job descriptions, and notes remain
   strictly on the user's local disk. No third-party SaaS fees or API key management.
2. Anti-Hallucination & Truth Enforcement:
   Never invent skills, titles, metrics, or responsibilities. Tailoring means
   rephrasing, reordering, prioritizing, and mapping terminology—never fabricating.
3. ATS-First Machine Compatibility:
   Single-column structure, clean hierarchy, standard section headers, no graphic
   skill bars, no tables that break parsers, and strict page budgeting (1 page for
   <10 years experience; exactly 2 pages for 10+ years).
4. User Clarity & Confidence:
   The candidate must always understand what changed, why it changed, and how
   well the resulting document matches the target job posting.

-- Updated schema for applications table
CREATE TABLE IF NOT EXISTS applications (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  company_name TEXT NOT NULL,
  company_slug TEXT NOT NULL,
  role_name TEXT NOT NULL,
  role_slug TEXT NOT NULL,
  stage TEXT NOT NULL DEFAULT 'tailored', -- 'tailored', 'applied', 'screening', 'interviewing', 'offer', 'archived'
  status TEXT,                          -- Legacy compatibility column ('applied', etc.)
  applied_attempt_id INTEGER REFERENCES application_attempts(id) ON DELETE SET NULL,
  applied_at TEXT,
  salary_min INTEGER,
  salary_max INTEGER,
  salary_currency TEXT DEFAULT 'USD',
  location TEXT,
  work_model TEXT,                      -- 'remote', 'hybrid', 'onsite'
  job_url TEXT,
  job_description_raw TEXT,
  match_score INTEGER,                  -- 0 - 100
  match_analysis_json TEXT,             -- JSON breakdown of hard/soft skills matched/missing
  recruiter_name TEXT,
  recruiter_email TEXT,
  recruiter_linkedin TEXT,
  follow_up_due_date TEXT,
  notes TEXT,
  archived_reason TEXT,                 -- 'rejected', 'ghosted', 'declined', 'withdrawn'
  created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  UNIQUE(user_id, company_slug, role_slug)
);

CREATE INDEX IF NOT EXISTS idx_applications_user_stage ON applications(user_id, stage);
CREATE INDEX IF NOT EXISTS idx_applications_follow_up ON applications(user_id, follow_up_due_date);

-- Application Activity Log Table for CRM timeline
CREATE TABLE IF NOT EXISTS application_activities (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  application_id INTEGER NOT NULL REFERENCES applications(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  activity_type TEXT NOT NULL,          -- 'stage_change', 'note_added', 'interview_scheduled', 'follow_up_sent'
  title TEXT NOT NULL,
  description TEXT,
  event_date TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now'))
);
CREATE INDEX IF NOT EXISTS idx_activities_app ON application_activities(application_id);

7. API CONTRACTS & BACKEND ENDPOINTS SPECIFICATION
================================================================================

7.1 Pipeline Management Endpoints (routes_applications.py)
- `GET /api/applications/pipeline`
  Returns grouped dictionary of applications by stage:
  `{ "tailored": [...], "applied": [...], "screening": [...], "interviewing": [...], "offer": [...], "archived": [...] }`

- `PATCH /api/applications/{application_id}/stage`
  Updates application stage and logs activity:
  Request Body: `{ "stage": "screening", "activity_note": "Phone screen with recruiter scheduled for Friday" }`

- `GET /api/applications/{application_id}`
  Returns complete application record, attempts history, match breakdown, and activity log.

- `PATCH /api/applications/{application_id}/details`
  Updates CRM details: salary, notes, recruiter contacts, follow-up date, etc.

- `POST /api/applications/{application_id}/activities`
  Appends an event/note to the application activity log.

- `GET /api/applications/analytics`
  Returns search funnel counts, conversion rates, average match score, and stage duration statistics.

7.2 AI Tailoring & Copilot Endpoints (app.py)
- `POST /api/tailor/{run_id}/bullet/quick-action`
  Micro-revision for a single bullet point:
  Request: `{ "bullet_text": str, "action_type": "add_metric" | "shorten" | "stronger_verb", "extra_context": str }`
  Response: `{ "updated_bullet": str }`

- `POST /api/applications/{application_id}/interview-prep`
  Generates predicted interview questions and STAR talking points based on the application's stored JD and tailored CV record.

- `POST /api/applications/{application_id}/draft-followup`
  Generates a personalized, concise follow-up email to the recruiter.
